# GitHub 注册踩坑实录（2026-11-25）

账号：liu-chengye
结论先行：注册成功，账号已开启 2FA。过程中踩了四个坑，全部记录在下面，每条都按"现象 / 原因 / 解法 / 以后怎么避免"写。

## 坑一：点"下一步"弹"访问暂时受限"

现象
填完邮箱、密码、用户名，点 Create account，不出现验证拼图，直接跳到一张写着"访问暂时受限"的页面，下面列出三条原因，并给出一个 IP 地址。

原因
这是 GitHub 用的人机验证服务（Arkose）在 IP 层做的风控拦截，不是账号问题，也不是浏览器问题。实测该 IP 为 39.91.1.31，归属中国山东济南、联通、ASN 4837（China169 骨干网），是宽带共享出口，被判定与网络爬虫同源。

解法
1. 手机开个人热点，必须用 4G/5G 流量，不能选"共享当前 WiFi"；
2. 电脑断开家里 WiFi，连热点；
3. 打开浏览器的无痕窗口，重新进 github.com/signup 填表；
4. 这一轮验证拼图就正常出了。

以后怎么避免
注册这类"要过风控"的写操作，默认走手机流量。家里宽带这个 IP 段已经被标记，短期内换浏览器、清 cookie 都没用。

## 坑二：无痕窗口用错了地方

现象
注册完再登录，发现每次都要重新走一遍验证，感觉"每一步都被卡"。

原因
无痕窗口关闭就清 cookie，登录态存不住，每次都是全新会话，自然每次都触发风控。

解法
无痕窗口只在第一次注册时用。注册成功后，改用普通窗口登录一次，保持登录状态，日常浏览直接走家里 WiFi。

以后怎么避免
区分两类操作：注册、建仓库、上传文件这类写操作可能触发风控，必要时切热点；看代码、看仓库这类读操作，普通窗口直连即可。

## 坑三：拿未注册的账号去登录页，必然提示密码不对

现象
在 Sign in to GitHub 页面填了 liu-chengye 和密码，提示不正确。

原因
那个页面是登录页，不是注册页。账号当时还没建成，填任何组合都会报错。

解法
点页面下方 New to GitHub? Create an account 回到注册页；注册成功后会有一条绿色横幅"Your account was created successfully! Please sign in to continue."，这时候再去 Sign in 就正常了。

以后怎么避免
认准两个入口：右上角 Sign up 是注册，Sign in 是登录。注册完先看有没有那条绿色横幅，有横幅才算账号建成。

## 坑四：恢复码截图外发，等于暴露一次

现象
2FA 设置第二步会展示 16 组恢复码，浏览器同时把 github-recovery-codes.txt 下载到 Downloads 目录。

原因
恢复码是"手机丢了还能进账号"的唯一凭证，任何人拿到就能登录。

解法
1. 抄一份纸质或存 U 盘；
2. 回 Settings → Password and authentication → Recovery codes → Regenerate 重新生成，旧批立即作废；
3. 把 Downloads 里那份旧文件删掉；
4. 新的一批只存两处：离线介质 + 手机私密备忘录。

以后怎么避免
恢复码、密码、邮箱验证码这三样，一律不截图、不发群、不发给任何 AI 助手。做短视频时如果拍到这一屏，必须整屏打码。

## 补充：账号安全一次性收尾清单

1. 2FA 已开（短信或 Microsoft Authenticator 二选一，国内都能用）；
2. 恢复码已重生成并离线保存；
3. 邮箱已验证（Settings → Emails 显示 Verified）；
4. 个人资料填了 Bio 和 Location；
5. 第一个仓库建好，README 里写清项目一句话说明。
